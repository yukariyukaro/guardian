# API 设计规范

[contracts/openapi.yaml](../contracts/openapi.yaml) 是路径、请求/响应、DTO、枚举、分页、错误及示例的唯一 API 事实源。本文只规定设计与交付门禁，不复制 schema，不代表契约中的全部能力已经实现。产品与隐私见 [PRD](戒网瘾机构公共监督平台-PRD.md)，验证见 [测试与质量规范](测试与质量规范.md)。

## 1. 契约先行与兼容

1. 先明确用户任务、模块、owner、验收、公开/私有字段、权限、状态、错误和隐私风险，再更新独立、版本化的 OpenAPI 3.1。
2. 契约先定义 schema、合成 examples、成功/空/错误情况和安全条件，经评审、lint、示例验证与兼容检查后，从同一版本生成类型及 Mock，再并行实现前后端。
3. 不从 ORM 实体、页面、Mock 或后端临时 DTO 反推契约；不手改生成文件，不用断言或 `any` 掩盖漂移。生成类型不替代运行时验证。
4. 删除/重命名字段、改变类型/必填/nullable/枚举、收紧请求约束、改变分页/错误/权限语义均须评估破坏性。响应枚举扩展也考虑旧客户端穷尽分支；先批准版本、兼容期与迁移顺序，再改实现。
5. 契约声明、实际注册路由、Mock 和真实响应建立逐操作覆盖；未实现项明确阻塞，不让校验示例或部分路由通过冒充完整接口已交付。

## 2. 公开投影与隐私

- 公开读取只返回经事实核查、隐私审核、法律/安全检查和人工 Publisher 终审的 `PUBLISHED` 版本，以逐字段白名单构造 DTO；不直接序列化数据库实体，新增私有列不能自动公开。
- 内部主键与稳定公开 key 隔离；数据、搜索、缓存、审核、审计和 fixtures 按模块隔离。平台装配层不直接读取模块业务数据；跨模块仅用明确授权的只读聚合接口。
- 不返回投稿/原始材料、联系方式、个人身份/定位、审核笔记/人员、内部撤回原因/法律意见、内部风险分数、文件/备份路径、凭据或未发布版本。同样约束关联、计数、地区字典、错误及元信息。
- 不存在、草稿、隐藏、撤回按契约采用一致安全响应，不暴露私有状态；关联接口先验证父对象可见性，公开引用只能指向公开资源。撤回来源时重新核查依赖陈述，缓存失效不能复活旧正文。
- 具体机构/事件陈述须有可公开来源；待核实只允许中立占位，匿名/D 级材料不公开具体指控。已关联回应须有相应来源，不把机构声明当作已经确认的事实。事件、报道、复核日期独立，未知值不造日期。
- 公开更新时间只随公开版本变化，不暴露私有审核活动。metadata 字典完整、无重复，仅来自允许公开的信息。

## 3. 输入、查询与错误

- 字段命名、包裹结构、排序与上限只在 OpenAPI 维护。未知/重复参数、未知字段、非法枚举、超限、数字文本格式及空值严格按契约处理，不静默截断或清洗后放行。
- 请求允许的必要类型转换与响应验证分离；响应禁止强制类型转换、填默认值或移除额外字段。校验长度、格式、唯一性和嵌套白名单，跨资源/跨字段条件另加语义断言。
- 列表总数、关联来源数与筛选字典仅计算公开数据；分页和稳定排序一致，未知日期按契约处理。客户端不能只取第一页却呈现为完整档案。
- 错误码与 HTTP 状态保持契约语义；未知/畸形错误安全失败。message/details 不回显输入值、未知参数名、堆栈、SQL、内部路径或身份；字段提示只用已知公开字段或通用请求名。
- 可选公开请求标识使用独立、不编码身份的服务端随机引用；不把任意公众传入的标识作为持久日志关联。安全消费 `Retry-After` 等契约 header，不暴露限流内部策略。
- 正文作为安全纯文本，不执行原始 HTML。外链仅允许经审核公开的 HTTP(S)；拒绝凭据/敏感参数、私有存储和内网目标，复核重定向。服务端抓取须限制协议、域名、地址、大小与时间，防止 SSRF；前端提示和 URI schema 不能替代安全检查。

## 4. 写入、权限与状态（启用前门禁）

未被契约和当前任务批准的能力保持关闭，不凭计划提前注册可用接口。P0 只允许更正/回应/隐私举报文字进入私有处理队列，不接收真实受害者投稿或文件，不直接改公开内容。

- 写入先定义长度/大小/类型、未知字段拒绝、反滥用/限流、幂等/重放、并发版本冲突、保存期限、错误和审计语义；未获服务端确认不返回受理成功。
- 管理/内部接口由服务端验证身份、角色、资源权限、状态转换和审计；客户端 role、manifest、隐藏按钮、风险等级和审核结果不能授权。
- Researcher 不发布，Reviewer 不替代 Publisher；事实/隐私/法律检查及双人复核或已批准延迟二次自审不可跳过。发布、隐藏、撤回明确理由；状态、投影与审计原子提交，陈旧操作不自动覆盖或重放。
- 数据库私有网络与角色隔离；迁移显式执行、采用兼容迁移并在隔离环境演练，不在服务启动时自动运行破坏性迁移。后端/运维/内容资料私有，不因本地同目录就获准开源。
- 日志仅记录必要事件、状态、时间、版本与安全引用，不记录正文、完整 URL/query、Cookie、Authorization、身份或连接串；生产/真实材料不能进入开发测试或外部模型，包括脱敏派生物。
- 后期多渠道接入另行评审，只写私有投稿队列，验签、限流、幂等、隔离与审计。AI 只提供机器信号；自动发布默认关闭，危机不自动回复，L2/L3 不绕过人工核查/隐私审核/终审。未来低风险自动化须独立批准、评测、抽样、熔断和撤回演练。

## 5. 合流验收

确认当前脚本后执行契约 lint、示例/Mock/真实响应验证、生成类型漂移及破坏性检查；再验证公开投影、不可见性、分页关联、权限/状态、错误、日志与真实集成/E2E。UI/Mock 通过不能证明服务端授权、事务或发布撤回已实现。缺失门禁报告阻塞，保持不可合并/不可发布，最后经人工内容/隐私及相关专项 review。
